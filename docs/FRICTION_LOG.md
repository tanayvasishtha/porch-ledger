# Friction log

Each entry: the task, what we did, what we expected, what happened, how bad it was, the workaround, and one suggestion. Severity: blocker (could not continue on that path), major (cost hours or forced a design change), minor (cost minutes).

## Ring Partner API and Developer Playground

### 1. Simulated events carry no classification
- **Task:** test our visit logic against Ring's own person and vehicle detection.
- **Steps:** triggered the Playground's Package, Vehicle and Motion simulations, then read event history.
- **Expected:** events typed as motion with a `sub_type` of vehicle or human, like the webhook docs describe.
- **Actual:** every simulated event comes back as `on_demand`. The Playground simulates live view sessions, not motion events, and it sends no webhooks, so the `motion_detected` path with `sub_type` cannot be exercised at all without a real device.
- **Severity:** major.
- **Workaround:** we classify frames ourselves with Amazon Rekognition and keep Ring's `sub_type` as an optional extra signal for real devices.
- **Suggestion:** let the Playground emit `motion_detected` webhooks with a chosen `sub_type`, so partners can test the documented event path end to end.

### 2. No package classification in the Partner API
- **Task:** detect deliveries from Ring data.
- **Steps:** read the motion webhook and event history docs for a package signal.
- **Expected:** a package sub type, since the Ring app shows package alerts.
- **Actual:** `sub_type` is one of motion, human, vehicle or other_motion. Package detection is not exposed to partners.
- **Severity:** major.
- **Workaround:** our own box detection on snapshots.
- **Suggestion:** expose the package alert as a `sub_type`, or say plainly in the docs that it is not available to partners.

### 3. Playground tokens last 30 minutes
- **Task:** keep a deployed worker polling the Playground.
- **Steps:** stored the token in SSM and scheduled the worker.
- **Expected:** a refresh path for sandbox tokens.
- **Actual:** the token expires after 30 minutes and must be regenerated by hand in the browser.
- **Severity:** minor.
- **Workaround:** we record full sessions into replayable tapes and run live only in short windows.
- **Suggestion:** offer a longer-lived sandbox token or a refresh token for the Playground.

### 4. Media retry guidance is easy to miss
- **Task:** download clips right after an event.
- **Steps:** requested a clip for a just-finished event.
- **Expected:** a clear rule for when media becomes available.
- **Actual:** 416 and 425 responses are expected for fresh events, and the retry advice (5, 10, 20, then 30 second waits, stop 2 minutes after the range ends) sits inside the Media Clips page rather than in Error Handling.
- **Severity:** minor.
- **Workaround:** implemented that schedule in our client.
- **Suggestion:** repeat the retry schedule in the Error Handling section, next to the status codes.

### 5. What TAKE encryption means for partner apps is unclear
- **Task:** decide whether a vision-based partner app still works once TAKE is the default.
- **Steps:** read the August developer news, the TAKE support article and the white paper.
- **Expected:** a direct statement of what partner apps can access under TAKE.
- **Actual:** the news says TAKE "narrows what your integrations can access"; the white paper says keys power "features active on your account". Neither says whether an installed Appstore app counts as an active feature.
- **Severity:** major (it affects whether the product can ship).
- **Workaround:** none; we document the open question in PRIVACY.md.
- **Suggestion:** add a partner FAQ entry: which Partner API media endpoints keep working under TAKE and under E2EE.

## Fire TV and Vega

### 6. Vega SDK does not run on Windows or WSL
- **Task:** build for Vega OS from a Windows desktop.
- **Steps:** read the Vega SDK system requirements.
- **Expected:** at least WSL support, since Vega targets Linux tooling.
- **Actual:** "Windows and WSL aren't supported or tested"; only macOS and native Ubuntu.
- **Severity:** blocker for Vega (we built for Fire OS instead).
- **Workaround:** Kotlin and Compose for TV on Fire OS 8, tested on the Android TV emulator.
- **Suggestion:** support WSL2 with KVM, or a cloud-hosted Vega Virtual Device, so Windows developers can try Vega.

## Alexa+

### 7. No way to test an Alexa+ add-on
- **Task:** connect our MCP server to Alexa+.
- **Steps:** followed the MCP Toolkit quick start.
- **Expected:** a developer simulator, given the hackathon framing that Alexa+ is open to outside developers.
- **Actual:** the toolkit, CLI and web simulator are preview only for select partners. The FAQ confirms there is no access path.
- **Severity:** major.
- **Workaround:** a web client on an iPad that is a real MCP client, styled after the add-on design guide.
- **Suggestion:** open the web simulator to everyone in read-only mode, even without publishing rights.

## AWS

### 8. Promotional credits ran out mid-hackathon
- **Task:** request the $150 AWS credit.
- **Expected:** credits available until the published October 21 cut-off.
- **Actual:** codes ran out on October 7.
- **Severity:** minor for us (free tier covers the build), major for teams relying on Bedrock.
- **Workaround:** stayed inside the free tier with a $5 budget alarm in the template.
- **Suggestion:** state the credit pool size up front.

### 9. AWS CLI v2 installer needs admin rights on Windows
- **Task:** install the AWS CLI without administrator access.
- **Steps:** `winget install Amazon.AWSCLI --scope user`.
- **Actual:** "No applicable installer found"; the MSI is machine-wide only. SAM CLI had the same problem.
- **Severity:** minor.
- **Workaround:** `uv tool install awscli` and `uv tool install aws-sam-cli`.
- **Suggestion:** ship a per-user installer for both CLIs.

### 10. Strands Agents pins the MCP SDK below 2.2
- **Task:** use the MCP Python SDK 2.3 for the server and Strands for the agent in one package.
- **Actual:** every current `strands-agents` release requires `mcp<2.2`, which forced a downgrade to 2.1.1 and changed client behaviour in our tests.
- **Severity:** major.
- **Workaround:** pinned mcp 2.1.1 and used the documented legacy connect mode in tests.
- **Suggestion:** relax the upper bound, or document the supported MCP range in the Strands release notes.

### 11. SAM HTTP API and function environment create a cycle
- **Task:** pass the HTTP API's host into the API function so the MCP transport can allow it.
- **Actual:** an `HttpApi` event on the function plus `!Ref HttpApi` in its environment is a circular dependency.
- **Severity:** minor.
- **Workaround:** declared the integration, route and permission resources explicitly.
- **Suggestion:** document the pattern in the SAM HTTP API guide.
